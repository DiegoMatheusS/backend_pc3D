CONTRATO RÁPIDO — FRONTEND CRIABYTE
Busca de Ofertas + IA por botões + Hardware/Produto separados

============================================================
1. BUSCA DE OFERTAS
============================================================

Acesso inicial:
- ADMIN: sim
- EDITOR: sim
- REVISOR: não nesta versão
- USUARIO: não

Rota sugerida no React:
/perfil/busca-ofertas

Backend:
GET /api/admin/busca-ofertas

Query params opcionais:
- busca=rtx 5070
- tag=PLACA_VIDEO
- descontoMinimo=20
- ordenar=MAIOR_DESCONTO

Tags:
PLACA_VIDEO
PROCESSADOR
PLACA_MAE
MEMORIA_RAM
SSD
FONTE
GABINETE
MONITOR
NOTEBOOK
PERIFERICOS
OUTROS

Ordenação:
MAIOR_DESCONTO
MENOR_PRECO
MAIOR_PRECO
MAIS_RECENTES

Atualizar/reler o banco:
POST /api/admin/busca-ofertas/atualizar

Status:
GET /api/admin/busca-ofertas/status

REGRA ATUAL:
Não existe integração automática com API do Mercado Livre.
A Busca de Ofertas lê diretamente o banco do CriaByte e mostra somente Ofertas que:
- estão ATIVAS;
- não estão vencidas;
- pertencem a Produto ativo;
- pertencem a Parceiro ativo;
- possuem urlAfiliada preenchida.

Portanto, quando o fluxo de cadastro de Produto também cadastrar uma Oferta com link afiliado, esse item aparece automaticamente em Busca de Ofertas.
O link afiliado continua pertencendo à entidade Oferta, preservando:
Hardware != Produto != Oferta.

A Busca de Ofertas não duplica registros e não cria Hardware, Produto ou Oferta.
O botão Atualizar apenas relê os dados atuais do banco.

2. IA PÚBLICA — BOTÕES PRIMEIRO
============================================================

Menu local, sem Gemini:
GET /api/ia/menu

Resposta possui:
interfaceSugerida.modo = BOTOES
interfaceSugerida.botoes = [...]

O botão “Perguntar livremente à IA” é o único atalho do menu que indica:
usaGemini=true

Ao pedir “Quero montar um PC”, se o uso não estiver definido, o backend devolve botões:
- Jogos
- Trabalho
- Estudos / Programação
- Uso geral

Esses botões chamam diretamente:
POST /api/ia/montagem-guiada

A montagem guiada também devolve:
interfaceSugerida.botoes

O frontend deve priorizar esses botões/cards em vez de transformar tudo em texto.

============================================================
4. HARDWARE E PRODUTO AGORA SÃO INDEPENDENTES
============================================================

POST /api/hardwares
cria SOMENTE Hardware.

Não cria Produto.
Não publica Produto.
Não cria Oferta.

Para selecionar Hardwares ainda sem Produto:
GET /api/admin/produtos/hardwares/disponiveis
GET /api/admin/produtos/hardwares/disponiveis?busca=ryzen

Para criar Produto comercial a partir de Hardware existente:
POST /api/admin/produtos/de-hardware/:hardwareId

Body opcional:
{
  "nome": "Nome comercial opcional",
  "descricao": "Descrição comercial opcional",
  "imagemUrl": "https://...",
  "imagemHoverUrl": "https://...",
  "publicado": false,
  "ativo": true,
  "ofertaInicial": {
    "parceiroId": 1,
    "urlOriginal": "https://loja.exemplo/produto",
    "urlAfiliada": "https://link-afiliado.exemplo/produto",
    "preco": 3699.90,
    "precoAnterior": 4199.90
  }
}

`ofertaInicial` também pode ser enviada em POST /api/admin/produtos.
Ela é opcional. Se for enviada, Produto + Oferta são criados na mesma transação: se a Oferta falhar, o Produto também não fica criado pela metade.
O backend define produtoId/hardwareId internamente. O frontend não deve enviá-los dentro de ofertaInicial.
A urlAfiliada é obrigatória dentro de ofertaInicial para que o item possa aparecer imediatamente na Busca de Ofertas.

Se não enviar os campos opcionais, o Produto usa nome/marca/modelo/MPN/GTIN/imagem do Hardware como pré-preenchimento.

O Hardware não é alterado pela criação/edição comercial do Produto, exceto pelo vínculo produtoId.

Arquivar Hardware não arquiva Produto.
Arquivar Produto não arquiva Hardware.
Excluir Hardware permanentemente não apaga Produto; o vínculo técnico é removido pelo banco.

6. COMUNIDADE — AVALIAÇÃO E PREÇO HISTÓRICO
============================================================

- POST /api/comunidade/builds/:id/avaliacao aceita uma única avaliação por usuário/build.
- Nova tentativa do mesmo usuário retorna 409; a nota existente não é alterada.
- Ao publicar uma build, precoNaPublicacao recebe o total das melhores ofertas ativas somente quando TODAS as peças possuem Hardware vinculado e preço público confiável.
- Se existir peça externa ou sem oferta, precoNaPublicacao = null.


============================================================
7. IA GUIADA SEM CRÉDITOS + ABRIR NO PC 3D
============================================================

Regra de custo:
- O fluxo padrão da IA pública é local e orientado por botões.
- GET /api/ia/menu retorna manterCampoTextoLivre=false.
- O botão PERGUNTAR_IA abre o campo livre; ao enviar, o frontend deve mandar usarGemini=true em POST /api/ia/chat.
- Sem usarGemini=true, mensagem livre NÃO chama Gemini e o backend devolve o menu local.
- POST /api/ia/montar-pc agora usa seleção determinística do catálogo + motor de compatibilidade; não chama Gemini.
- POST /api/ia/montagem-guiada continua 100% local.

Ao chegar em etapa=RESUMO, a resposta inclui:
redirecionamento3D = {
  automaticoSugerido: true,
  acaoFrontend: "ABRIR_PC_3D",
  usarEstadoTemporario: true
}

O frontend pode então abrir automaticamente o PC 3D usando visualizacao3D.
Não é necessária nova chamada à IA para essa transição.

8. DASHBOARD — VERIFICAR PREÇOS DAS OFERTAS
============================================================

Status para o Dashboard:
GET /api/admin/ofertas/verificacao-precos/status
Permissões: ADMIN, EDITOR e REVISOR (somente leitura).

Executar verificação:
POST /api/admin/ofertas/verificar-precos
Permissões: ADMIN e EDITOR.
Body opcional:
{ "limite": 20 }
Limite permitido: 1 a 50 por lote.

O backend verifica Ofertas ATIVAS ou INDISPONIVEIS que tenham urlAfiliada, Produto ativo, Parceiro ativo e validade vigente.
A consulta é sequencial para evitar rajadas contra lojas externas.

Regras de segurança/confiabilidade:
- tenta primeiro urlOriginal e usa urlAfiliada como fallback;
- segue poucos redirecionamentos, sempre revalidando destino público;
- bloqueia localhost, IPs privados e URLs com credenciais;
- aceita somente HTTP/HTTPS e HTML com tamanho limitado;
- só atualiza preço quando encontra valor estruturado confiável (JSON-LD Offer/Product ou meta de preço);
- não tenta adivinhar preço por texto/classes CSS;
- falha/bloqueio/HTML sem preço NÃO altera o preço salvo;
- HTTP 404/410 confirmado nas fontes ou disponibilidade estruturada pode marcar INDISPONIVEL;
- se uma oferta antes indisponível voltar com preço confiável, ela volta para ATIVA;
- mudança de preço grava precoAnterior e HistoricoPrecoOferta.

Resposta resumida:
{
  "verificadas": 20,
  "atualizadas": 3,
  "semAlteracao": 12,
  "indisponiveis": 1,
  "falharam": 4,
  "restantesElegiveis": 17,
  "resultados": []
}

O botão do Dashboard pode repetir lotes enquanto restantesElegiveis > 0.
Não existe integração com API de busca do Mercado Livre; esta função apenas confere URLs que o administrador já cadastrou.
