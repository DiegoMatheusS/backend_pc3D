CRIABYTE — LOGIN / CADASTRO COM GOOGLE
======================================

BACKEND
-------
Endpoint único para cadastro e login:

POST /api/auth/google
Content-Type: application/json

Body:
{
  "credential": "ID_TOKEN_JWT_RETORNADO_PELO_GOOGLE"
}

Resposta 200:
{
  "usuario": {
    "id": 123,
    "nome": "Nome do usuário",
    "email": "usuario@gmail.com",
    "papel": "USUARIO",
    "ativo": true
  },
  "expiraEm": "...",
  "novoUsuario": true
}

novoUsuario=true  -> primeira entrada; a conta foi criada.
novoUsuario=false -> a conta já existia ou foi vinculada pelo mesmo e-mail.

O backend grava a mesma sessão HttpOnly usada pelo login tradicional.
O frontend NÃO deve armazenar o token de sessão do CriaByte em localStorage.

CONFIGURAÇÃO DO BACKEND
-----------------------
Adicionar ao .env local/produção:

GOOGLE_CLIENT_ID=SEU_CLIENT_ID.apps.googleusercontent.com

Opcional, se futuramente existirem vários clientes (web/mobile):
GOOGLE_CLIENT_IDS=CLIENT_ID_2,CLIENT_ID_3

GOOGLE_CLIENT_ID e GOOGLE_CLIENT_IDS não são client secrets.
O backend não precisa receber o client secret para validar o ID token do
Google Identity Services usado neste fluxo de autenticação.

FRONTEND
--------
Usar Google Identity Services (GIS), não a biblioteca Google Sign-In antiga.
O callback do Google recebe um objeto cujo campo `credential` contém o ID token.
Enviar exatamente esse valor para POST /api/auth/google.

Exemplo conceitual:

google.accounts.id.initialize({
  client_id: import.meta.env.VITE_GOOGLE_CLIENT_ID,
  callback: async (response) => {
    await fetch('/api/auth/google', {
      method: 'POST',
      credentials: 'include',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ credential: response.credential }),
    });
  },
});

A tela de Cadastro e a tela de Login podem usar o MESMO endpoint e o MESMO
botão "Continuar com Google". O backend decide se cria ou apenas entra.

REGRAS IMPLEMENTADAS
--------------------
1. O ID token é validado no servidor com google-auth-library.
2. O audience precisa corresponder ao GOOGLE_CLIENT_ID/GOOGLE_CLIENT_IDS.
3. O e-mail do Google precisa estar verificado.
4. O identificador permanente salvo é o `sub` do Google, não o e-mail.
5. Conta Google nova nasce sempre com papel USUARIO.
6. Se já existir conta CriaByte com o mesmo e-mail e o Google for autoridade
   sobre o endereço (Gmail ou Google Workspace), ela é vinculada sem apagar a
   senha atual e sem alterar o papel atual.
7. Para e-mail externo usado como Conta Google (ex.: provedor de terceiros),
   uma conta local preexistente não é vinculada automaticamente; isso evita
   tomada de conta por colisão de e-mail.
8. Conta desativada não consegue entrar pelo Google.
9. O login tradicional por e-mail e senha continua funcionando normalmente.
10. O google_sub não é exposto nas respostas públicas da API.

GOOGLE CLOUD / GIS
------------------
Criar uma credencial OAuth 2.0 do tipo "Web application" e configurar as
origens JavaScript autorizadas do frontend, por exemplo durante desenvolvimento:

http://localhost:5173

Na produção, adicionar também a origem HTTPS real do frontend CriaByte.
O VITE_GOOGLE_CLIENT_ID do frontend e o GOOGLE_CLIENT_ID do backend devem
corresponder ao cliente usado para obter a credential.
